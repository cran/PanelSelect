Migrating from PanelSelect 1.0.1 to 2.0.0

The main change is one fitting function, panel_select(), with common controls and standard fitted-object methods. This guide maps the four panel-selection functions in 1.0.1 to version 2.0.0 and highlights changes that can affect results.

Refit saved 1.0.1 analyses from their original data. Their result lists are not current panelselect objects and cannot be passed directly to the new methods.

1. Update the fitting call

Table 1. Replace model-specific functions with one fitting interface
Outcome Function in 1.0.1 Current panel_select() family
Linear probitRE_linearRE() "linear"
Binary probitRE_probitRE() "probit"
Poisson probitRE_PoissonRE() "poisson"
Poisson-lognormal probitRE_PLNRE() "pln"

The outcome formula now comes first, followed by selection, data, ID and family. Named arguments avoid mistakes when translating old positional calls. For example, using dat from the main vignette:

# PanelSelect 1.0.1
old = probitRE_linearRE(d ~ x + w, y ~ x + w, id.name = "id", data = dat)
# PanelSelect 2.0.0
fit = panel_select(
  outcome = y ~ x + w,
  selection = d ~ x + w,
  data = dat,
  id = "id",
  family = "linear")
summary(fit)

The same interface also fits cross-sectional Linear, binary and PLN selection models with id = NULL, and standalone panel probit, Poisson and PLN models with selection = NULL. Keep unselected rows in selection models; their outcome may be NA.

2. Translate settings and parameter names

Table 2. Common argument and control changes
Setting in 1.0.1 Current equivalent

rho_off = TRUE (Linear/binary); disable_rho = TRUE (PLN) fixed = c(cor_re = 0)
tau_off = TRUE (Linear/binary); disable_tau = TRUE (PLN) fixed = c(cor_error = 0)
rho.init, tau.init, or supplied parameter values Named natural-scale values in start, using Table 3
H (Linear/binary) control = panel_control(quadrature = "gh", nodes = H)
method, reltol, factr, verbose Arguments of panel_control(); use trace instead of verbose
use.optim = FALSE (Linear/binary default) control = panel_control(optimizer = "maxLik"); the current default is optim() with BFGS

Count-model offset_w_name, offset_x_name offset() terms in the selection and outcome formulas

For count models, old H = c(h1, h2) becomes nodes = c(selection = h2, outcome = h1). PLN also uses observation_nodes = h2. This preserves the intended orders, not identical numerical results. The current defaults are fixed GH with 10 nodes per person effect and 20 nodes for PLN’s separate observation integral.

start accepts any subset of the current names; init supplies the rest. fixed holds named parameters at their supplied values. Supply natural-scale values, not optimizer coordinates. Free SDs must start positive; fixed SDs may be zero where allowed. Correlations must lie strictly between −1 and 1.

The Linear/binary functions in 1.0.1 ignored par; current start values are honored. When transferring estimates, use the old estimates table and map its names explicitly. Do not copy raw $par or $estimate indiscriminately: their scales differed across the old functions.

3. Read results through methods

Table 4. Replace direct component access with fitted-object methods
Result in 1.0.1 Current method
$estimates[, "estimate"] coef(fit)
$estimates summary(fit)$coefficients; confint(fit) for intervals
$var, $var_bhhh, $var_hessian, $se vcov(fit); SEs in summary(fit)$coefficients[, "se"]
$LL, $maximum, $value logLik(fit)
$AIC, $BIC AIC(fit); use BIC(fit, unit = "observations") for the old row-count convention
$predict$respond_prob, $predict$prob predict(fit, newdata, type = "selection_probability")
$predict$outcome, $predict$outcome_prob predict(fit, newdata, type = "response")
$predict$actual_outcome predict(fit, newdata, type = "joint")
$predict$pop_mean predict(fit, newdata, type = "response", aggregate = TRUE)

Predictions are requested after fitting; add se.fit = TRUE for their standard errors. type = "response" is the potential-outcome mean, while type = "selected_mean" is the mean among selected observations. Population predictions remain the default. type = "joint" gives the mean observed contribution, counting unselected outcomes as zero. History-conditioned predictions require explicit history data and GH/AGH at the applicable integration levels.

BIC(fit) now counts independent panels by default. For covariance alternatives, request vcov(fit, type = "observed") or vcov(fit, type = "opg") explicitly.

4. Understand changes in results

Matching formulas and integration orders does not guarantee the same estimates or standard errors as 1.0.1. The main reasons are:

  • Starting values. The current default uses separate random-effects models for panel selection. The old Linear/binary default used pooled regressions; choose init = "pooled" to use that approach. The old count models already used random-effects auxiliaries.
  • Standard errors. The default is now vcov = "opg", based on independent-unit score outer products. The old Linear/binary functions preferred the inverse Hessian; choose vcov = "observed" to request observed information. Invalid requested covariance remains unavailable rather than being replaced silently.
  • Corrected calculations. Fixes to derivatives, parameter transformations and rare-probability calculations can change estimates or standard errors. Formula offset() terms ignored by the old Linear/binary functions now enter their predictors with coefficient one.
  • Numerical accuracy. Adaptive GH and GL provide alternatives to fixed GH. Use check_stationarity() and check_quadrature() to assess a new fit, and compare estimates under common, checked settings. Convergence alone does not establish integration accuracy or a global maximum.

See the main vignette for a short checking workflow, and the fitting, control and prediction help for additional options.
